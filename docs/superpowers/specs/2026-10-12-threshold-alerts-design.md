# 后台阈值告警

用户已确认实现 CPU、内存、磁盘阈值告警及第三方通知。

## 行为与配置

- 左侧导航新增管理员专属「告警通知」独立页面，配置持久化在现有 SQLite 数据库。
- 默认关闭。CPU、内存、磁盘规则分别配置开关及 1–100% 阈值。
- 使用严格大于比较；磁盘按挂载点独立判断。
- 超限持续时间默认 60 秒，可设 0–3600 秒；重复通知间隔默认 900 秒，可设 60–86400 秒。恢复到阈值及以下时结束该次告警，下一次超限重新计时。
- 采样超过 10 秒未更新时不发告警，并重置连续超限计时。使用单调时钟计时。
- 支持企业微信群机器人、Server酱 Turbo（个人微信）、通用 HTTPS Webhook；单个服务器配置一个当前渠道。
- 渠道凭据仅后台保存，读取接口只返回是否已配置；更新时留空保留原凭据，切换渠道需要新凭据。页面不使用 localStorage 存储凭据。
- 测试通知使用已保存的渠道，与总开关无关，由管理员显式点击发送；限制测试请求频率。
- 通知包含服务器名、指标、挂载点（磁盘）、当前值、阈值、持续时间、采集时间。通用 Webhook 使用 JSON。
- 显示最近 100 条发送结果，SQLite 持久化；不保存渠道凭据或第三方原始错误。

## 后台与接口

`alerts.py` 封装配置校验、持久化、状态机、渠道发送和独立后台线程；沿用标准库及 psutil，无新增运行依赖，支持 Python 3.9+。

规则线程每 2 秒读取最新快照，使用有界队列交给独立发送线程，网络请求不持有采集锁或规则锁。整体发送期限为 5 秒，期限到达时中断套接字；响应长度有限，不跟随重定向。固定微信服务域名，通用 Webhook 仅允许 HTTPS。不可取消的 DNS 查询使用有界后台线程，晚返回的查询在发出请求前检查取消状态。失败记录可读错误，并按重复间隔重试，防止发送失败造成刷屏。关闭或修改配置后，下一轮判断使用新配置，丢弃已失效的排队告警；已发送的请求最多等待整体期限。

- `GET /api/admin/alerts`：脱敏配置、当前超限项、最近发送结果。
- `PATCH /api/admin/alerts`：完整配置更新，验证管理员、来源和 CSRF。
- `POST /api/admin/alerts/test`：已保存渠道的测试通知，验证管理员、来源和 CSRF。

后端线程由服务启动、关闭时统一管理。Dockerfile 复制新模块。前端独立 `alerts.js` 使用现有表单、主题及移动端样式。独立页面不等待监控指标加载；配置接口不可用时显示错误与重试入口，首次指标恢复不覆盖表单编辑。浏览器资源提醒保持现有偏好，其说明明确仅作用于页面。

## 验证

测试严格边界、持续时间、恢复、重复间隔、逐磁盘判断、陈旧采样、禁用、发送失败、配置持久化与凭据脱敏、管理员和 CSRF。渠道测试仅拦截 HTTP 传输，检查真实编码和第三方业务错误；不发送实际外部通知。浏览器验证配置保存、刷新后保留、测试按钮与发送结果，以及成员权限、移动端和深色显示。
